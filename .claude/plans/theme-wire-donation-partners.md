# Theme-repo prompt: wire the donation map to read assets/donation-partners.json

Open a new Claude session in `rubies-ecom-v4` and paste the prompt below.

---

We're moving the donation partner list out of theme section blocks and into a static JSON asset that's published from `rubies-automations`. This makes `rubies-automations` the single source of truth (the donation_partners table there feeds both CS routing AND this map), and partner updates no longer require theme edits.

## Contract

A file already exists at `assets/donation-partners.json` (committed on main from a sibling repo). It's a JSON array; each element has these keys (exact casing — the array is generated by `customer-service/lib/donationPartnersPublish.js` in rubies-automations):

```ts
{
  name:        string  // org name
  address:     string  // multi-line "RUBIES Returns\nc/o ORG\n..." mailing block (ready to render verbatim)
  description: string
  sizeRange:   string  // e.g. "Youth sizes 4-8, Adult XS - 4X"
  imageUrl:    string  // absolute CDN URL of the org logo
  orgUrl:      string  // org's external website
  lat:         number
  lng:         number
}
```

`assets/donation-partners.json` will be updated by an automated branch push from rubies-automations (branch pattern `data/donation-partners-<stamp>`). **Do not hand-edit this file** — it gets overwritten on every publish.

## What to change

The current donation map lives in:

- `sections/preloved-returns-map.liquid` — section with type `preloved-returns-map`, currently loops `section.blocks` (block.type=`organization`) and serializes each block.settings.* into a JS `partners` array that drives a Google Maps initMap call.
- `templates/page.donate-preloved.json` — page template that instantiates that section with ~14 hardcoded organization blocks.

Replace the in-Liquid partners array with a runtime fetch of `{{ 'donation-partners.json' | asset_url }}`. Concretely:

1. **In `sections/preloved-returns-map.liquid`:**
   - Remove (or default to empty) the Liquid loop that builds the `partners` array from `section.blocks`. Around lines 178-190 today.
   - Inside the script, replace `const partners = [...];` with an async fetch:
     ```js
     async function loadPartners() {
       const res = await fetch({{ 'donation-partners.json' | asset_url | json }});
       if (!res.ok) throw new Error('Failed to load donation-partners.json: ' + res.status);
       return res.json();
     }
     ```
   - Change `initMap` (or the existing Google callback) to call `loadPartners()` first, then run the existing rendering logic with the resolved array. Keep the Google Maps script tag and callback wiring exactly as-is — only the data source changes.
   - The JSON keys already match what the existing code uses (`name`, `address`, `description`, `sizeRange`, `imageUrl`, `orgUrl`, `lat`, `lng`), so the rendering loop body shouldn't need to change.

2. **In `templates/page.donate-preloved.json`:**
   - Delete the 14 `organization` blocks under `preloved_returns_map.blocks` and clear `block_order`.
   - Keep the `preloved_returns_map` section itself.
   - That's it — the section now self-loads data, so its blocks array is intentionally empty.

3. **Section schema:**
   - Remove the `organization` block schema from the section's `{% schema %}` so the theme editor stops offering "add organization" (the data is no longer manually managed here).

## Behavior considerations

- The map will be empty for ~50-200ms on first load while fetch resolves. If that's a noticeable flash, add a tiny "Loading partners..." placeholder; otherwise just live with it.
- Temporarily breaking the page is acceptable (per Jamie). Test locally first via `/preview`.
- The JSON is small (~14 entries, well under 10KB). No need for caching headers beyond Shopify's defaults.
- If `fetch` fails, surface an unobtrusive error to the console and a friendly "Couldn't load the partner list — please refresh" in the map container. Don't crash the page.

## Once that's working

Run `/preview` to get the branch preview URL, eyeball the donation page, then `/ship` when satisfied. After ship, rubies-automations can publish updates by appending to its `donation_partners` table and pushing the JSON, with no further theme changes needed.

## Verifying

Open the donation page on the preview theme. The map should show the same 14 partners with their logos, addresses, and "Donate Here" links. The info-panel "click a marker" UX should be unchanged. Run `assert(window.__partners_count === 14)` or similar from devtools to confirm.
